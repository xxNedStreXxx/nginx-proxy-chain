# Nginx Proxy Chain 🚀

Декларативное динамическое проксирование и построение цепочек прокси (Proxy Chaining) на базе Nginx без использования условных операторов `if` внутри локаций (**Zero-If Architecture**) с полноценным Enterprise-стеком автоматизированного мониторинга (**Observability Provisioning**).

---

## Архитектура проекта

Проект реализует механизм последовательного проксирования HTTP-запросов через цепочку независимых узлов Nginx на основе управляющего заголовка `X-Next-Hop` и сквозного идентификатора запроса `X-Request-ID`.


### Ключевые особенности:
* **Обход ограничений "If Is Evil":** Переключение динамических маршрутов реализовано через нативные таблицы подстановок (`map`), атомарный `rewrite` и именованные локации (`error_page`). Это гарантирует 100% наследование всех HTTP-заголовков (включая `X-Forwarded-For`) по всей цепочке.
* **Трассировка цепочки (Proxy Loop Detection):** Автоматическое построение пути прохождения запроса в заголовке `X-Proxy-Loop` с защитой от зацикливания. При обнаружении петли проксирования узел возвращает HTTP-статус `508 Loop Detected`.
* **Distributed Tracing & Cloud-Native Observability:** Каждый внешний запрос получает сквозной `X-Request-ID`. Логи Nginx пишутся в однострочном формате **JSON Escape**. Легковесный агент **Promtail** собирает их напрямую через системный сокет Docker (`/var/run/docker.sock`) и доставляет в **Grafana Loki**. Метрики собираются через **Nginx Exporter** и доставляются в **Prometheus**.
* **Полная автоматизация (Infrastructure as Code):** При запуске инфраструктуры источники данных (Prometheus, Loki) и интерактивный дашборд аналитики импортируются в Grafana автоматически (**Data Sources & Dashboards Provisioning**).
* **Защита от IP-Spoofing:** На внешнем шлюзе (порт 80) заголовки клиентов жестко валидируются, предотвращая подмену IP-адресов извне, в то время как внутренний контур (порт 8080) безопасно накапливает историю хостов.

## Конфигурация Nginx (Алгоритм работы)

Вся логика ветвления вынесена на уровень `http` в блоки `map`. Они работают как быстрая таблица поиска, вычисляя переменные "на лету" на уровне ядра Nginx:

1. **Парсинг цепочки:** Из заголовка `X-Next-Hop` регулярным выражением POSIX (`[[:space:]]`) выделяется первый хост (`$next_destination`), а остаток строки передается дальше (`$remaining_chain`).
2. **Контроль петель:** Строка `"$http_x_proxy_loop:$hostname"` проверяется по маске. Если текущий хост уже обрабатывал этот запрос — выставляется flag зацикливания.
3. **Маршрутизация без IF:** В секции `location /` выполняется атомарный `rewrite` во внутренний виртуальный URI (например, `/nginx2` или `/loop`). Nginx переходит в соответствующий скрытый блок, генерирует нужный статус-код и через `error_page` отправляет запрос в систему именованных локаций `@...`.
4. **Восстановление URI:** Перед отправкой запроса на следующий узел с помощью `rewrite ^ $request_uri break;` полностью восстанавливается оригинальный URI клиента, что позволяет беспрепятственно проксировать запросы к любым веб-приложениям без искажения путей.

## Тестирование и верификация

В репозитории настроен автоматический пайплайн **GitHub Actions**, который разворачивает тестовый стенд в Docker Compose (с ограничением памяти до 128М на сервис) и последовательно выполняет следующие тесты:

* **Тест 1 (Прямой запрос):** Проверка базового проксирования напрямую в конечное приложение `whoami`.
* **Тест 2 (Длинная цепочка):** Запрос через последовательность `Nginx 1 -> Nginx 2 -> Nginx 3 -> App` с валидацией полной цепочки IP-адресов в `X-Forwarded-For`.
* **Тест 3 (Защита от спуфинга):** Проверка неизменяемости цепочки при попытке передать поддельный заголовок `X-Forwarded-For` через внешний шлюз.
* **Тест 4 (Анти-петля):** Симуляция циклического маршрута и проверка мгновенного возврата прокси-сервером ошибки `HTTP 508 Loop Detected`.
* **Тест Observability:** Проверка готовности всей системы мониторинга (Loki и Prometheus) с использованием отказоустойчивых циклов ожидания (SRE Retry Loops с флагами `--retry-connrefused`).

## 🛠️ Автоматизация развертывания (Ansible IaC)

Для управления конфигурацией и деплоя цепочки прокси-серверов вне Docker-окружения (на bare-metal серверах или виртуальных машинах) в проект интегрирована Ansible-роль `nginx_proxy`. Это позволяет полностью автоматизировать установку веб-сервера и динамически генерировать конфигурации.

### Особенности реализации:
* **Изолированная роль:** Вся логика установки и настройки инкапсулирована внутри роли `roles/nginx_proxy`.
* **Zero-Downtime переконфигурация:** Применение изменений в `nginx.conf` происходит атомарно через встроенные обработчики (`handlers`). Команда `nginx -s reload` вызывается только в том случае, если конфигурационный файл действительно изменился.
* **Динамические Jinja2-шаблоны:** Конфигурация Nginx формируется на лету на основе переменных инвентаря, исключая жесткий хардкод портов и адресов следующих узлов.

### Структура каталога автоматизации:
```text
ansible/
├── roles/
│   └── nginx_proxy/
│       ├── tasks/
│       │   └── main.yml        # Установка пакетов и деплой конфигурации
│       ├── templates/
│       │   └── nginx.conf.j2   # Шаблон конфигурационного файла Nginx
│       └── handlers/
│           └── main.yml        # Триггер безопасной перезагрузки сервиса
└── deploy.yml                  # Главный плейбук для запуска сценария
```

### Инструкция по запуску:

1. Подготовьте файл инвентаря `inventory.ini`, описав в нем целевые хосты цепочки и их переменные (входной порт, а также хост и порт следующего прокси-сервера):
   ```ini
   [proxy_nodes]
   nginx1 ansible_host=192.168.1.11 proxy_port=8081 next_proxy_host=192.168.1.12 next_proxy_port=8082
   nginx2 ansible_host=192.168.1.12 proxy_port=8082 next_proxy_host=app_server  next_proxy_port=80
   ```

2. Запустите применение конфигурации ко всей цепочке серверов одной командой:
   ```bash
   ansible-playbook -i inventory.ini ansible/deploy.yml
   ```



## Развертывание локально

Для локального запуска всей инфраструктуры и автоматического развертывания дашбордов мониторинга выполните команды:

```bash
# Клонировать репозиторий
git clone https://github.com
cd nginx-proxy-chain

# Запустить инфраструктуру
docker compose up -d
```

### Доступные веб-интерфейсы:
* **Grafana UI:** `http://localhost:3000` (Вход свободный, встроен дашборд **"Nginx Proxy Chain Telemetry"** с графиками RPS, распределения HTTP-статусов и живым стримом Trace-логов).
* **Панель Prometheus:** `http://localhost:9090`
* **API базы логов Loki:** `http://localhost:3100/ready`
